QUESTION
========
Exercise 3.1: Build a Travel Package

A travel company allows customers to customise a travel package.
A package can include:
    - Destination: Auckland, Sydney, Melbourne, etc.
    - Hotel: 3-star, 4-star, 5-star
    - Transport: Flight, Train, Bus
    - Meal plan: None, Breakfast, Full Board
    - Activities: City Tour, Museum, Adventure Tour
    - Insurance: Yes/No

Your task is to use the Builder Pattern to construct a travel package
step by step.

Reference - the Builder Pattern is used when we need to create a complex
object step by step. Instead of one complicated constructor:
    Computer("Intel i7", 16, "1TB SSD", "RTX 4060", "Windows 11")
we build it one part at a time:
    computer = ComputerBuilder()
    computer.set_cpu("Intel i7")
    computer.set_ram(16)
    my_computer = computer.build()


ANSWER
======
The Builder Pattern separates building an object from the finished
object itself. The builder collects the customer's choices one at a time
and only creates the TravelPackage when build() is called. Every setter
returns the builder, so the calls can be chained and read like a
sentence.

Design:
    1. TravelPackage (product):
         - Holds destination, hotel, transport, meal_plan, activities
           and insurance.
         - show_package(): prints the package.

    2. TravelPackageBuilder (builder):
         - set_destination(), set_hotel(), set_transport(),
           set_meal_plan(), add_activity(), set_insurance().
         - Each one stores the choice and returns self (this is what
           allows chaining).
         - Defaults: meal plan "None", no activities, no insurance.
         - Hotel, transport, meal plan and activity are checked against
           the allowed options.
         - build(): raises ValueError if destination, hotel or transport
           is missing, otherwise returns a TravelPackage.

    3. TravelDirector (director):
         - build_budget_package(builder)  -> Auckland, 3-star, Bus
         - build_family_package(builder)  -> Sydney, 4-star, Flight,
                                             Breakfast, City Tour +
                                             Museum, insured
         - build_luxury_package(builder)  -> Melbourne, 5-star, Flight,
                                             Full Board, all three
                                             activities, insured

    4. Building a package directly, without the director:
           package = (
               TravelPackageBuilder()
               .set_destination("Melbourne")
               .set_hotel("4-star")
               .set_transport("Train")
               .set_meal_plan("Full Board")
               .add_activity("Adventure Tour")
               .set_insurance(True)
               .build()
           )

Output when run (first package shown):
    --- Budget package (built by the director) ---
    Destination : Auckland
    Hotel       : 3-star
    Transport   : Bus
    Meal plan   : None
    Activities  : None
    Insurance   : No


MORE QUESTIONS AND ANSWERS (FOR BETTER UNDERSTANDING)
=====================================================

Q1. What is the Builder pattern, in simple words?
A1. It is a way to create a complex object one step at a time. Think of
    ordering a custom computer or a pizza: you pick each part, then ask
    for the finished result. The builder remembers the choices and puts
    the object together at the end.

Q2. What are the parts of the pattern in this program?
A2.     1. Product  -> TravelPackage
        2. Builder  -> TravelPackageBuilder
        3. Director -> TravelDirector
        4. Client   -> the code at the bottom of main.py

Q3. Why not just use a constructor with six arguments?
A3. With six values it is easy to swap two of them by mistake, and the
    call is hard to read:
        TravelPackage("Sydney", "4-star", "Flight", "Breakfast", [...], True)
    With the builder every value is labelled by the method that sets it,
    and parts the customer does not care about can simply be left out.

Q4. Why does every setter end with "return self"?
A4. Returning the builder lets the next call be written straight after
    the previous one (method chaining):
        builder.set_hotel("4-star").set_transport("Train")
    Without "return self" the first call would return None and the
    second call would fail.

Q5. What does the director do, and is it required?
A5. The director stores common recipes, so the client does not repeat the
    same steps. It is not required: the customer can call the builder
    directly for a custom package (see the "Custom package" block in the
    demonstration).

Q6. Why does each package in the demonstration get a NEW builder?
A6. The builder keeps its choices between calls. If one builder were
    reused, the first package's activities would still be in it and would
    leak into the second package. A new TravelPackageBuilder() per
    package is the simplest way to start clean. (build() also hands the
    package a copy of the activities list, so changing the builder later
    cannot alter a package that was already built.)

Q7. What happens if a required part is missing?
A7. build() raises a ValueError:
        TravelPackageBuilder().set_destination("Sydney").build()
        -> ValueError: A package needs a destination, hotel and transport.
    This stops half-finished packages from being created.

Q8. What happens if the customer picks an option that does not exist?
A8. The setter checks the value against the allowed options and raises a
    ValueError straight away:
        TravelPackageBuilder().set_hotel("2-star")
        -> ValueError: Invalid hotel '2-star'. Choose from: 3-star,
           4-star, 5-star
    Failing at the setter points at the exact mistake, instead of
    letting a bad value travel into the finished package.

Q9. How are activities different from the other parts?
A9. A customer can pick several activities, so add_activity() appends to
    a list instead of replacing a single value. Adding the same activity
    twice is ignored.

Q10. How is the Builder pattern different from the Factory patterns
     (ACT_8_2 and ACT_8_3)?
A10.    Factory patterns                 Builder
        create an object in ONE call     creates an object in MANY steps
        focus on WHICH class to create   focus on HOW a complex object is
                                         assembled
    Use a factory to choose between types. Use a builder when one type
    has many optional or ordered parts.

Q11. What is a real-life example of this pattern?
A11. Ordering at a sandwich shop. You choose the bread, filling, sauce
     and extras one by one, and the sandwich is only made at the end. A
     "meal deal" is the director: a fixed recipe you can order in one go.
