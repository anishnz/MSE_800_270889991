=== List_com_2.py ===

QUESTION
--------
Use a list comprehension to flatten a matrix, e.g. turn
[[1, 2, 3], [4, 5, 6], [7, 8, 9]] into a single flat list of numbers.

ANSWER
------
A 3x3 numpy matrix is created from the nested list, and a nested list
comprehension ("for row in matrix for element in row") loops over each
row and then over each element inside it, collecting everything into
one list called flattened_matrix.

However, because a numpy matrix object always stays 2-dimensional
(even a single row keeps the shape 1xN rather than becoming a plain
1D array), the inner loop "for element in row" only runs once per row
and yields that row again rather than its individual numbers. So the
actual output is a list of the 3 original rows, not 9 flat numbers:

    [matrix([[1, 2, 3]]), matrix([[4, 5, 6]]), matrix([[7, 8, 9]])]

This is a well-known quirk of iterating over numpy matrix objects (as
opposed to plain numpy arrays or plain Python lists of lists, where the
same nested comprehension would correctly flatten to [1, 2, 3, 4, 5, 6,
7, 8, 9]).


=== enumerate_for_looping.py ===

QUESTION
--------
Given grades = [88, 92, 78, 65, 50, 94], use enumerate() in a for-loop
to add 5 bonus points to every grade, except the 5th grade, which
should get 10 bonus points instead.

ANSWER
------
enumerate(grades) is used in the for-loop so that both the index and the
grade value are available on each iteration. An if/else checks whether
the current index equals 4 (the 5th item, since indexing starts at 0):
if so, 10 points are added; otherwise, 5 points are added. The result is
written back into the list at the same index.

Output when run:
    [93, 97, 83, 70, 60, 99]

=== main.py ===

QUESTION
--------
Given keys = ['a', 'b', 'c', 'd'] and values = [1, 2, 3], create a
dictionary from the two lists.

ANSWER
------
zip(keys, values) pairs up items from both lists by position, and
dict() converts those pairs directly into a dictionary. Because keys
has 4 items but values only has 3, zip() stops as soon as the shorter
list (values) runs out, so the extra key 'd' is simply dropped from the
result.

Output when run:
    {'a': 1, 'b': 2, 'c': 3}

=== mergining_Dicti.py ===

QUESTION
--------
Given Key1 = ['a','b','c','d','f','g','h','e','a'], Value1 = [20, 3, 1,
88, 55, 92, 6, 90, 910], Key2 = ['u','b','o','x','e','a'], and Value2 =
[200, 30, 10, 88, 55, 920], build a dictionary from each key/value pair
of lists, merge the two dictionaries together, and keep only the
key-value pairs where the value is an odd number.

ANSWER
------
dict(zip(Key1, Value1)) and dict(zip(Key2, Value2)) turn each pair of
parallel lists into a dictionary (dict1 and dict2). The two dictionaries
are then merged with {**dict1, **dict2}; where the same key appears in
both (here 'b', 'e' and 'a'), the value from dict2 (unpacked second)
overwrites the value from dict1. Finally, a dictionary comprehension
filters merged_dict to keep only the entries whose value is odd
(value % 2 != 0).

Output when run:
    {'c': 1, 'f': 55, 'e': 55}

('a' and 'b' end up with even values from dict2 after the merge, and
'd', 'g', 'h' have even values in dict1, so none of those keys survive
the odd-value filter; 'c' keeps its odd value of 1 from dict1 since
dict2 has no 'c' key to overwrite it; 'f' keeps 55 from dict1 for the
same reason; 'e' ends up 55, taken from dict2's value which overwrote
dict1's 90.)
