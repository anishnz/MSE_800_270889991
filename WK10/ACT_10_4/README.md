# Part C: Working with Files

## Problem Statement

Write `read_first_line(path)` that returns the first line of a text
file.

- If the file does not exist, print a helpful message and return
  `None`.
- If the file cannot be read because of permissions, print a different
  message and return `None`.
- Use `with` so the file is always closed.
- Extension: modify the function so it re-raises a custom
  `DataFileError` (using `raise ... from`) instead of printing, and
  handle that error in the calling code.

## Requirements

1. `read_first_line(path)` - opens with `with`, returns the first line
   without its trailing newline.
2. Missing file -> `FileNotFoundError` caught, message printed, `None`
   returned.
3. Unreadable file -> `PermissionError` caught, a *different* message
   printed, `None` returned.
4. `DataFileError` (extension) - a custom exception; `read_first_line_strict()`
   raises it with `raise DataFileError(...) from error`, keeping the
   original `FileNotFoundError`/`PermissionError` attached instead of
   printing anything itself.

## How It Works

- `with open(path, ...) as file:` guarantees the file handle is closed
  when the block ends - even if an exception is raised inside it. There
  is no way to forget the matching `file.close()`, because there isn't
  one to forget.
- `file.readline()` reads only the first line, keeping its trailing
  `"\n"`; `.rstrip("\n")` removes just that one trailing newline (not
  any other whitespace), leaving a clean string.
- A missing path raises `FileNotFoundError` the moment `open()` runs,
  before the `with` block's body executes at all - caught, a message is
  printed, `None` is returned.
- A path that exists but cannot be opened for reading raises
  `PermissionError`. On this Windows machine, trying to `open()` a
  **directory** as if it were a file also raises `PermissionError`,
  which is used in the demo below to trigger that branch without
  needing to change any real file permissions.
- The extension, `read_first_line_strict()`, does the identical job but
  swaps `print(...); return None` for
  `raise DataFileError(...) from error`. `from error` attaches the
  original exception as `__cause__`, so nothing about the root cause is
  lost - it is just handed to the caller to decide what to do with,
  instead of being printed here.

## Running the Program

```bash
python main.py
```

### Expected Output

```
--- Reading an existing file ---
'Hello from the first line'

--- Reading a file that does not exist ---
Could not find the file: does_not_exist.txt
None

--- Reading a directory instead of a file (raises PermissionError) ---
Do not have permission to read the file: <this folder's path>
None

--- Extension: read_first_line_strict() raises DataFileError ---
Caught DataFileError: Could not find the file: does_not_exist.txt
Original cause: FileNotFoundError: [Errno 2] No such file or directory: 'does_not_exist.txt'
```

(`main.py` creates `sample.txt` itself on every run, so the first case
is always reproducible.)
