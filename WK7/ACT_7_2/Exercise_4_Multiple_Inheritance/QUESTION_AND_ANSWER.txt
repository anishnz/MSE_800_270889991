QUESTION
========
Exercise 4: Multiple Inheritance - University Student Academic + Contact Information

Problem Statement
A university wants to record both academic information (programme, GPA)
and contact information (email, phone) for each student, but neither
piece of information fits neatly under the other.

Task: Demonstrate multiple inheritance in Python by creating one child
class that inherits from two unrelated parent classes at the same time.

Requirements
Create the following classes:
    1. AcademicInfo - holds programme, gpa, and a method to display
       academic info.
    2. ContactInfo - holds email, phone, and a method to display
       contact info.
    3. Student (inherits from BOTH AcademicInfo and ContactInfo) - adds
       a name and a method that displays everything together.


ANSWER
======
MULTIPLE INHERITANCE means ONE child class inherits from MORE THAN ONE
parent class at the same time:

    AcademicInfo       ContactInfo      <-- two separate parents
             \             /
              \           /
                Student                 <-- one child, inherits BOTH

Design:
    1. AcademicInfo (first parent, independent of ContactInfo):
         - __init__(self, programme, gpa): stores both values.
         - display_academic_info(self): prints programme and GPA.

    2. ContactInfo (second parent, independent of AcademicInfo):
         - __init__(self, email, phone): stores both values.
         - display_contact_info(self): prints email and phone.

    3. Student(AcademicInfo, ContactInfo) (child inheriting from both):
         - __init__(self, name, programme, gpa, email, phone): calls
           AcademicInfo.__init__(self, programme, gpa) and
           ContactInfo.__init__(self, email, phone) EXPLICITLY by class
           name, rather than using super(), because with two parents
           that both define __init__, relying on super()'s Method
           Resolution Order (MRO) chaining would be less explicit about
           which constructor runs with which arguments. It then stores
           name as an attribute unique to Student.
         - display_details(self): prints the student's name, then
           calls display_academic_info() and display_contact_info(),
           both of which are inherited - one from each parent.

    4. The demonstration code creates one Student (Priya Sharma, BSc
       Computer Science, GPA 3.8, with email and phone), displays all
       the combined details, and uses isinstance() to confirm the
       Student object is recognised as BOTH an AcademicInfo and a
       ContactInfo. It also prints Student.__mro__ (Method Resolution
       Order), which lists the exact order Python searches through
       Student -> AcademicInfo -> ContactInfo -> object when looking up
       an attribute or method - this becomes important whenever
       multiple parent classes could define the same method name.

    This design shows the benefit of multiple inheritance: Student
    combines two unrelated sets of behaviour (academic and contact)
    without needing to duplicate either parent's code, and without
    those two parents needing any relationship to each other.

Output when run:
    ---- Student Details (Academic + Contact) ----
    Name      : Priya Sharma
    Programme : BSc Computer Science
    GPA       : 3.8
    Email     : priya.sharma@example.edu
    Phone     : 98-1234-5678

    Is student1 an AcademicInfo? True
    Is student1 a ContactInfo?   True

    Method Resolution Order (MRO):
     -> Student
     -> AcademicInfo
     -> ContactInfo
     -> object


MORE QUESTIONS AND ANSWERS (FOR BETTER UNDERSTANDING)
=====================================================

Q1. What does "multiple inheritance" mean?
A1. ONE child class inherits from TWO OR MORE parent classes at the same
    time. Student inherits from both AcademicInfo and ContactInfo, so a
    Student object can use methods from both parents.

Q2. How is the class written in code?
A2. List the parents in brackets, separated by a comma:
        class Student(AcademicInfo, ContactInfo):

Q3. Why does Student call AcademicInfo.__init__(...) and
    ContactInfo.__init__(...) by name instead of using super()?
A3. The two parents need DIFFERENT arguments (programme and gpa, versus
    email and phone). Calling each parent's __init__ by name makes it
    obvious which values go where. super() would only start one chain
    through the MRO, and the parents would have to be written to
    cooperate with each other.

Q4. What is the MRO (Method Resolution Order) and why does it matter?
A4. It is the list of classes Python searches, in order, when looking
    for a method or attribute:
        Student -> AcademicInfo -> ContactInfo -> object
    It matters when BOTH parents have a method with the same name. The
    parent listed FIRST wins. Example:
        class A:  def hi(self): return "A"
        class B:  def hi(self): return "B"
        class S1(A, B): pass       # S1().hi() -> "A"
        class S2(B, A): pass       # S2().hi() -> "B"
    Changing the order of the parents changes the MRO and the result.

Q5. What is the "diamond problem"?
A5. It happens when two parents both inherit from the same grandparent,
    forming a diamond shape. It could make the grandparent's code run
    twice or make it unclear which version of a method to use. Python
    solves it with the MRO, which visits every class exactly once.

Q6. Why are AcademicInfo and ContactInfo good candidates for multiple
    inheritance?
A6. They are unrelated pieces of information. Neither is a kind of the
    other, but a Student needs both, so combining them lets Student reuse
    both without copying any code.
